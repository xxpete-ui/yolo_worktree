# C++ 部署流程评审与复现验证

评审对象为 `D:/Project/OpticalSelectionMachine/OnnxDeployLab` 中 CMake 的 `vision_pipeline` 目标。下文的 `src/`、`include/` 路径均相对于该工程。

## 换模型时会发生什么

| 位置                                                             | 原行为和影响                                                                                                                                                                                                                                       |
| ---------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/vision_pipeline.cpp:30,78`、`src/Classification.cpp:145`    | 加载分类器时要求旁边有恰好 28 行的 `labels.txt`，推理后还要求输出恰好 `[1,28]`。本次分类数据有 23 类，正常模型也会被拒绝。若换成类别顺序不同的另一个 28 类模型，旧标签文件能通过数量检查，显示的类名却可能错位。原模型的 ONNX 已内嵌有序 `names`。 |
| `src/ClassificationInput.cpp:53`、`src/Classification.cpp:13,93` | 裁剪画布、尺寸校验、输入张量三处固定为 224×224。当前旧模型元数据确实指定 224×224；训练尺寸改变时应同步改变裁剪和推理的尺寸。                                                                                                                       |
| `include/Segmentation.h:9`、`src/vision_pipeline.cpp:45,86`      | 分割模块允许传入设置，但可执行入口只收模型、单张图片和输出路径，固定采用 640×640、置信度 0.25、NMS IoU 0.45、掩膜概率 0.5。统一的 `bottle` 模型符合任务约定，这三个阈值会实际影响保留哪些瓶子及其边缘。                                            |
| `src/ClassificationInput.cpp:35,47`                              | 分类图保留最小旋转矩形内的原图像素。凹形瓶子周围的传送带、框进来的相邻瓶子可能也出现在分类输入。现有模型按该几何方式复现；是否需要改裁剪，应结合训练小图与实际误判判断。                                                                           |
| `src/vision_pipeline.cpp:98,110,136`                             | 所有图片都使用 `mask_1.png`、`cls_input_1.png`、`overlay.jpg` 等固定名字。多张图共用输出目录时同名文件会被覆盖，上一张多出的目标文件仍会留下。人工核查需要用原图与实例标识关联各项输出。                                                           |

原部署把两个 ONNX Runtime 会话建在目标循环外，每个瓶子分别给出分割分数与分类分数。轮廓为空或退化会跳过分类并保留检测，这些行为适用于批处理和人工检查。

## 像素与分数的计算路径

1. 分割输入保持宽高比，双线性缩放并用灰色 114 填满输入画布。宽高四舍五入后记录实际缩放比例和整数填边，BGR 转 RGB，按 255 归一化后以 NCHW 排布。见 `src/Segmentation.cpp:29,97`。
2. 单类检测头的第 5 个通道是 `bottle` 分数。仅保留分数严格大于 0.25 且有效的候选框，对网络坐标的浮点框做 NMS。反变换分别使用实际横纵倍率，左上取 floor，右下取 ceil，裁到原图。见 `src/Segmentation.cpp:50,256,280`。
3. 对保留实例，以系数和原型生成掩膜。在原型网格按半开检测框裁切，框内取 sigmoid 概率，框外清零。经双线性插值恢复网络画布、去除整数填边、再恢复原图，最后取严格大于 0.5 的像素。提前二值化会改变边缘。见 `src/Segmentation.cpp:129,160,184`。
4. 在该检测框的掩膜内取最大有效外轮廓，生成最小旋转矩形。四角坐标朝零取整以绘制实心多边形；外接裁框依据浮点角点，含 ceil 得到的右下像素。保留矩形内原图像素，外部置黑，保持原方向，只等比缩小超过画布的目标。放置偏移为 `画布尺寸 // 2 - 缩放后尺寸 // 2`，原入口关闭模糊。见 `src/ClassificationInput.cpp:23,35,44,53,66`。
5. 分类输入执行 BGR 转 RGB、按 255 归一化、HWC 转 NCHW。旧分类器输出已经过 softmax，直接读取最高分和它的类别索引。见 `src/Classification.cpp:22,57,150`。

**OpenCV 版本能改变裁剪结果。** 对 `_202505130858460415.jpg` 的第 3 个瓶子，两端提取到的外轮廓点逐点一致。OpenCV 5.0 交换最小旋转矩形的宽高并返回等效的负角度；计算角点时发生浮点差异，最大 x 从 1246.000000 变为 1246.000122。外接框右边界因此多出 1 像素，等比缩放后有 22,142 个输出像素变化。该瓶子的原分类置信度为 0.450445，5.0 得到 0.506541。另一例 `_202505130858120141.jpg` 的第 1 个瓶子，角点 y 从 166.000000 变为 165.999985，多边形填充取整后改变了 188 个输出像素。两端使用相同的 C++ 输入 PNG 后，87 个瓶子的分类分数最大差回落至 0.00000162。本次逐像素复现采用经过对照的 OpenCV 4.10.0。
